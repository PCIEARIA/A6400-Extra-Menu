# A6400 Extra-Menu 一鍵建置、部署與完整操作規範（V3.9 SSLF）

> **給開發者、AI 審查器與實機使用者的最新基準（2026-11-20，代號 SSLF / Sony Super LUT FILM）**：
> 本倉庫 `main` 分支已更新至 **Sony A6400 V3.9 SSLF**（以實機驗證之 V3.5.1 Fast SP 為基礎升級）——新增與改進：
> 1. **免強制開藍牙 + `/etc/a6400-autoexec.so`**：`HOOK_STUB` 與 `bootstrap-local.sh` 在 `/tmp_bt` 仍為唯讀根目錄時自動掛載 `size=2048k tmpfs`（失敗時寫入 `/tmp/a6400-hook-err.log`），不再強制要求保持 `Bluetooth = 開`。
> 2. **防截斷部署器 + 實機共享 Inode 防護 + `--rollback` / `--diag`**：[`tools/pmca_deploy_v3_clite.py`](../tools/pmca_deploy_v3_clite.py) 所有 shell 指令分塊至 `<= 180` 字元並於 `rc=None` 自動重試一次，掛載獨立 `2048k tmpfs` 暫存區（`/tmp_bt/v3c_up`），保留 `/etc` 與 `/tmp` 共用 `/dev/nflasha10` 掛勾（不誤刪 `/tmp/a6400-autoexec.so`），並支援 `extra_persistent_files`、一鍵恢復備份／清除掛勾（`--rollback`）與蒐集日誌（`--diag`）。
> 3. **多組自訂快門音（24 kHz Sony SDS ADPCM）與即時狀態顯示**：可選購編入三組音效槽位（`0x33 日文 Charo` / `0x34 Bling Bling` / `0x35 iPhone 快門`，無音檔時亦不影響編譯）或置於 SD 卡 `/A6400/CHARO.PCM`（或 `SHUTTER.PCM`，**須為 Sony 24 kHz SDS 32-byte ADPCM 格式、`1–29,760 B`**；裸無壓縮 PCM 會產生刺耳雪花雜音）；主標題與「膠片細節」分頁同步顯示即時轉檔數與 `1,024` 佇列容量。
> 4. **位元等價 `picojpeg.c` 加速 + MPR 穩定性調校**：主機實測 `6MP` `decode_ms` 由 `249 ms` 降至 `138 ms`（輸出位元 100% 一致）；實機穩定參數調為 `CAPTURE_WAIT_MS=4000u`、`CAPTURE_BASELINE_INTERVAL_MS=750u`、`CAPTURE_STABLE_MS=800u`，略過非錯誤 `[AVIMMGR]`/`[MprCnv]` 雜訊、修正重試後 `uncertain=1` 誤停，並於 `scan == -2`（`media_unavailable`，如接上 USB 大容量儲存）時透過 `transport_stop` 釋放 `mpr_monio.elf`。

## 快速一鍵總覽（從 GitHub 原始碼建置與部署）

```sh
# 步驟 1：取得公開原始碼並通過電腦端測試與公開檔案檢查
git clone https://github.com/PCIEARIA/A6400-Extra-Menu.git
cd A6400-Extra-Menu
python3 -m unittest discover -p 'test_*.py' -v
python3 tools/check_public_tree.py

# 步驟 2：一鍵交叉編譯並打包（有無 assets/a6400-charo-shutter.pcm 皆可直接建置）
sh tools/build_v3_clite.sh \
  /path/to/camera-libs \
  /path/to/camera-mpr_monio.elf \
  /path/to/camera-mwf_monio.elf \
  ./build-v39-sslf

# 步驟 3：另行準備 Sony-PMCA-RE（https://github.com/ma1co/Sony-PMCA-RE），相機接上 USB（大容量儲存）執行分塊寫入與雙向 SHA-256 校驗
# （新機首次安裝或遷移 /etc/a6400-autoexec.so，務必先從機身 /usr/lib/libAK8975.so 用 build_autoexec_hook.py 產生 a6400-autoexec.so 並加上 --install-hook）
sudo python3 tools/pmca_deploy_v3_clite.py \
  ./build-v39-sslf/local-boot-package \
  --pmca-dir /path/to/Sony-PMCA-RE \
  [--install-hook /path/to/a6400-autoexec.so]
```

> 打包預編譯 zip 時請先清理 `__pycache__` 與裸 `.pyc` 檔，避免多餘惰性位元碼混入發布包。

## 一、適用對象、相容性邊界與環境準備

### 1. 硬體與韌體版本檢查（務必在相機端核對）
- **適用機型與韌體**：**Sony ILCE-6400（A6400）FW `Ver. 2.00`**。
  - 請在相機螢幕打開 **`MENU` → `設定（工具箱）` → `版本`** 親自確認顯示 `Ver. 2.00`（Windows USB 大容量儲存模式僅露出磁碟機，無法從 PC 讀卡機判斷韌體版本）。
- **硬體架構釘選**：實機 CPU 為 ARMv7 Cortex-A5（`CPU part: 0xc05`、`vfpv3d16` / `vfpv4`，**無 NEON SIMD**），交叉編譯僅可使用 `-mcpu=cortex-a5 -mfpu=vfpv3-d16 -mfloat-abi=hard`，嚴禁擅自啟用 `-mfpu=neon`。
- **嚴禁跨機型套用**：UI 接駁（[`camera/native_film_ui_trial3.c`](../camera/native_film_ui_trial3.c)、[`camera/native_ui_load_guard.c`](../camera/native_ui_load_guard.c)）對 FW 2.00 符號與記憶體進行指紋驗證，不符會自動拒絕載入，切勿套用到其他機身或韌體。

### 2. 部署電腦必要條件（Windows 10+ WSL2 / Linux / macOS）
- **Python 3.8 以上 + 管理員權限**：
  - **Windows 10 / Windows 11（全面改用 WSL2 + `usbipd-win`）**：
    > ⚠️ **為什麼不再建議直接用 Windows 原生 Zadig**：大量 Windows 10 / Windows 11 機器因核心隔離（Memory Integrity）、驅動簽章或 USB 重新枚舉問題，導致 `libusb-win32` / Zadig 頻頻失效或卡在 `054C:0336`。**Windows 10（Build 19041+）與 Windows 11 一律建議改用 WSL2 + `usbipd-win` 在 Linux 環境安裝**，完全免改 Windows 驅動、穩定度與原生 Linux 相同！
    1. **首次安裝環境**（以**系統管理員身分開啟 PowerShell**）：
       ```powershell
       wsl --install
       winget install --exact dorssel.usbipd-win
       ```
       確認發行版為 WSL2（`wsl -l -v` 顯示 `VERSION 2`；**WSL1 不支援 USB 穿透**），進入 Ubuntu (WSL2) 安裝套件：
       ```sh
       sudo apt update && sudo apt install -y python3 python3-usb libusb-1.0-0 usbutils
       # 若需在 WSL2 內自行從源碼交叉編譯另加裝：
       sudo apt install -y gcc-arm-linux-gnueabihf g++-arm-linux-gnueabihf make git
       ```
    2. **將相機 USB 穿透至 WSL2（務必使用 `--auto-attach`）**：
       - 相機設為 `大容量儲存` 接上電腦後，於**系統管理員 PowerShell** 執行 `usbipd list` 找到 `054c:0ca8` 的 `BUSID`（如 `2-3`）：
       ```powershell
       usbipd bind --busid <BUSID>
       usbipd attach --wsl --auto-attach --busid <BUSID>
       ```
       - **保持該 PowerShell 視窗開啟勿關閉**！因為切進 PMCA 服務模式時相機會斷線再重連成 `054C:0336`，只有加上 `--auto-attach` 才會自動把重枚舉後的服務模式裝置接回 WSL2。
    3. **在 WSL2 內執行部署**：跑 `lsusb` 確認看到 `054c:0ca8`，切換至 Linux 路徑下的專案或解壓目錄直接執行 `sudo python3 tools/pmca_deploy_v3_clite.py ...`（或一鍵包 `sudo python3 oneclick_deploy.py`）。刷完後於 PowerShell 按 `Ctrl+C` 結束 `--auto-attach` 並拔線即可，Windows 讀卡功能完全不受影響。
  - **Linux（Ubuntu / Debian / Orange Pi）**：需 `python3`、`python3-usb`、`libusb-1.0-0` 與 `sudo`（或對應 udev 規則）；編譯另需 `gcc-arm-linux-gnueabihf`、`g++-arm-linux-gnueabihf`、`make`。
  - **macOS**：安裝官方 Python 3（非僅 Xcode stub）及 `libusb`／`pyusb`，並以 `sudo` 存取 USB；交叉編譯可透過 Homebrew 工具鏈或 Linux 容器進行。
  - *（僅舊版 Windows 不適用 WSL2 時之備案，不推薦）*：使用正式 Python 3.8+ 搭配 Zadig 對 `054C:0CA8` 與重開 Zadig 後的 `054C:0336` 皆更換為 `libusb-win32`（不可用 WinUSB）。

### 3. 相機與記憶卡準備
1. 相機保持滿電（建議 > 50%），插好測試記憶卡，並確認記憶卡側邊 **防寫鎖定（LOCK）撥片處於解鎖狀態**。
2. **相機系統語言設定（避免字型缺字方塊）**：
   - 使用**繁體中文正式版**（`main`）請確認相機 `MENU → 設定 → 語言` 為 **`繁體中文`**。
   - 若使用**簡體中文分支版**（`v3.9-sslf-sc`），請務必將相機系統語言設為 **`简体中文`**（因浮層選單調用機身原生字型渲染）。
3. **務必使用具資料傳輸功能的 Micro-USB 線**（僅能充電的線無法讓相機進入 PMCA）。
3. **Bluetooth 無須再強制保持開啟（V3.9 SSLF）**：
   - V3.5.1 與更早期版本曾需保持 `Bluetooth 功能 = 開` 讓 `startBTCore.sh` 掛載 `/tmp_bt`；自 **V3.9 SSLF** 起，開機掛勾 `/etc/a6400-autoexec.so` 與 `bootstrap-local.sh` 在 `/tmp_bt` 為唯讀根目錄時會自行掛載 `size=2048k tmpfs`（且 `libBTUtils.so` 後續檢查 `/proc/mounts` 已掛載則不重複疊掛），即使在飛航模式或藍牙關閉下也能冷開機啟動（若異常會留存 `/tmp/a6400-hook-err.log`）。
4. 開啟相機 `MENU` → `設定` 第 4 頁 → **`USB 連線`** 設為 **`大容量儲存（Mass Storage）`**，**`USB LUN 設定`** 維持 **`多重`**；切換過程相機進入服務模式（`054C:0336`）時螢幕可能變黑，在出現 `V3_CLITE_DEPLOY_OK` 與 `Done` 前**切勿拔線或關閉電源**。
5. **記憶卡檔案系統與資料夾建立（支援 FAT32 與 exFAT）**：
   - 開機期間 `bootstrap-local.sh` 不觸碰記憶卡（`native_sd_read=0`），拍攝後全程透過 Sony 原生 `mwf_monio` `IFSYS` 讀寫 `B:`/`A:`，因此 **`FAT32` 與大容量 `exFAT`（如 64GB / 128GB SDXC）皆可直接正常使用，無需刻意轉成 FAT32**。
   - **必做項目**：先在記憶卡最上層建立空資料夾 **`/A6400/TEST/`**（與 `/DCIM/` 並列）。
   - **可選自訂快門音效（必須使用 Sony 24 kHz SDS 32-byte ADPCM 格式）**：
     - 機身 `/usr/share/avsystemsound/*.bin` 採用 **24,000 Hz Sony 專有 32-byte SDS ADPCM**（每 32 bytes 含 1 byte `(mode<<4)|shift` 標頭 ＋ 31 bytes 有號差值）；**嚴禁直接放入裸 `16-bit LE PCM` WAV/PCM 原始樣本**，否則機身播放會變成刺耳的雪花雜音。
     - 若已在開機包啟用音效掛載，可將編碼完成之 `.pcm`（**`1 ~ 29,760` bytes**，即最多 `930` 幀、`1.201s`，不足由程式自動補零）放入記憶卡 **`/A6400/CHARO.PCM`** 或 **`/A6400/SHUTTER.PCM`** 覆寫第二組槽位（`0x34`）；若於建置時在 `assets/` 另行放入 `a6400-charo-connect.pcm`（`<= 24,768 B`、`0x33`）、`a6400-charo-shutter.pcm`（`<= 29,760 B`、`0x34`）、`a6400-charo-push.pcm`（`<= 18,560 B`、`0x35`），選單第 4 列即可於多組音效與關閉之間循環切換。

### 4. 從 A6400 拉取原廠編譯輸入檔（自行從源碼編譯／新機安裝 Hook 時需要）
透過 `Sony-PMCA-RE` 進入 `serviceshell` 後，拉取下列原廠檔案至開發機（不可提交到 Git）：
- `/lib/libc-2.11.2.so` 與 `/lib/libdl-2.11.2.so`
- `/usr/bin/mpr_monio.elf`（FW 2.00 SHA-256：`300ed9c5a90dc26c3390b5fdd85c5a6e4d5f26e24c6022aa56832f83a47a96bf`）
- `/usr/bin/mwf_monio.elf`
- `/usr/lib/libAK8975.so`（新機首次安裝須執行 `python3 tools/build_autoexec_hook.py libAK8975.so a6400-autoexec.so` 產生 `/etc/a6400-autoexec.so` 並在部署時加上 `--install-hook`；執行 `build_autoexec_hook.py` 需備妥 `arm-linux-gnueabihf-as` 與 `arm-linux-gnueabihf-objcopy`）

## 三、寫入目標 A6400 與冷開機驗收

> **安全鐵律**：寫入過程只寫檔案（data-only），**禁止在 PMCA USB shell 內直接熱執行守護行程或掛載 SD 卡**，一律靠拔線斷電冷開機啟動。

> **升級防卡死提醒（從 V3.5.x／舊版升級或重刷前必看）**：
> 若相機**已經**常駐執行舊版（V3.5.x 或尚未包含釋放修復之版本），接上 USB 後可能因背景常駐 `a6400-film-capture-daemon.elf` 與 `/usr/bin/mpr_monio.elf` 占用原生介面，導致 **`Switching to service mode`（`054C:0CA8 → 054C:0336`）逾時（`USBTimeoutError` / `[Errno 110]`）**。
> - **V3.9 SSLF（`package=7ec416fa937fab67`）已修復此行為**：實機於 `scan == -2`（`media_unavailable`）透過 `transport_stop(&transport)` 主動釋放 `mpr_monio.elf` 後，冷開機插線跑 `--diag` **無須 `/disable_hook` 即可一次從 `054C:0CA8` 切進 `054C:0336`**。
> - **從 V3.5.x 或遇到任何 `USBTimeoutError` 時的標準排障步驟**：
>   1. 相機接上 USB（大容量儲存）或用讀卡機，在記憶卡最上層建立空白檔 **`/disable_hook`** 與 **`/A6400/DISABLE`**，安全退出記憶卡。
>   2. 拔除 USB 線 → 相機關機再重新開機一次（讓該次開機在停用旗標下回到純原廠狀態，背景不啟動守護行程與 `mpr_monio.elf`）→ 再插回 USB。
>   3. 執行下方 `tools/pmca_deploy_v3_clite.py` 完成寫入與雙向 SHA-256 校驗（確認出現 `V3_CLITE_DEPLOY_OK`）。
>   4. **寫完務必刪除記憶卡上的 `/disable_hook` 與 `/A6400/DISABLE`**（忘記刪除會導致後續每次開機都被停用，選單完全不載入！），再拔線斷電（建議取出電池 10 秒）冷開機啟用新版。

1. 相機接上 USB 後執行部署腳本（`tools/pmca_deploy_v3_clite.py`）。
   - **首次安裝到新機／尚未安裝 Hook 的相機，請務必加上 `--install-hook`**：僅部署 `local-boot-package`（`/tmp/autoexec.sh` ＋ `/tmp/a6400-film-boot-v15.tar`）不會開機自啟；必須先用 `tools/build_autoexec_hook.py` 基於本機拉取的 `/usr/lib/libAK8975.so` 產生 `a6400-autoexec.so`，並在第一次部署或需要更新開機掛勾時加上 `--install-hook /path/to/a6400-autoexec.so`，才會寫入 `/etc/a6400-autoexec.so` 並設定 `/etc/ld.so.preload`。
   - **重要架構常識（`/etc` 與 `/tmp` 共用 `/dev/nflasha10` 同一個 Inode）**：A6400 原廠系統把 `/dev/nflasha10` 同時掛載在 `/etc` 與 `/tmp`（兩者檔案互相鏡像、`ls -lid /etc /tmp` inode 相同）。[`tools/pmca_deploy_v3_clite.py`](../tools/pmca_deploy_v3_clite.py) 已實機驗證會保留而不誤刪 `/tmp/a6400-autoexec.so`；**若你手動進 `serviceshell` 操作，嚴禁在更新 `/etc/a6400-autoexec.so` 後執行 `rm /tmp/a6400-autoexec.so`**，否則會將剛安裝的 `/etc/a6400-autoexec.so` 一併刪除！
   - 上傳與安裝過程會額外在 `/tmp_bt/v3c_up` 掛載 `size=2048k tmpfs`（避開 `/tmp_bt` 原僅 `1024k` 上限），全數指令分塊 `<= 180` 字元並內建 `rc=None` 重試，既有 `/etc/ld.so.preload`、`/etc/a6400-autoexec.so`、`/tmp/autoexec.sh` 與 `/tmp/a6400-film-boot-v15.tar` 會先保留 `.pre-v3c-backup`，雙向 SHA-256 校驗完成後印出 `V3_CLITE_DEPLOY_OK ... version=V3.9-SSLF`。
2. **完全斷電冷開機**：拔掉 USB 線 → 相機關機 → **取出電池 10 秒再裝回開機**。
3. **首輪冷開機驗收**：
   - 開機後等待 **35–40 秒**，**輕觸螢幕並放開一次** → 等約 2 秒。
   - **同時長按 `MENU ＋ 放大鏡` 約 2 秒**叫出浮層卡片（標題顯示 `A6400 V3.9 SSLF | 關閉` 或即時轉檔計數 `V3.9 SSLF | 開啟 | 已轉:N (M/1024)`）：
     - 第 1 列：`LUT 濾鏡: 關閉 / 開啟`
     - 第 2 列：`膠片風格`（可翻頁選擇 10 款預設）
     - 第 3 列：`膠片細節`（進入子選單調節 **顆粒強度 0–3** 與 **底片光暈 開/關**，或一鍵恢復預設）
     - （若編譯時含私人音效）第 4 列：`快門聲`
     - 左下角：`畫質: 1.7MP 極速` / `畫質: 6MP 高清`；右下角：`關閉`
   - 建議將相機「**自動檢視 (Auto Review)**」設為 **`關`**，拍照瞬間左下角會顯示橘色 `處理中...` → 完成顯示綠色 `OK 已存SD: ... (FxxxxNNN.JPG)`（`1.7MP` 約 `5.6~8.2 秒`、`6MP` 約 `17.5~21 秒`，依顆粒/光暈與 JPEG 大小而異）。

## 四、日常使用規範與安全邊界

| 項目 | 規範與硬性上限 | 說明 |
| --- | --- | --- |
| **開機待機** | 開機後等 **30–40 秒** | Guard 檢查 `im.elf` 並建立初始 DCF 掃描基線。 |
| **召喚前提** | **先輕觸並放開螢幕一次**，再長按 `MENU ＋ 放大鏡` 2 秒 | 未碰觸過螢幕前 UI 模組尚未在 Appframework 執行緒掛載。 |
| **最新夾張數上限** | 最新 `DCIM` 資料夾內 `.JPG` **< `1,024` 張** | 持久化版本 `MAX_FILES=1024u`（僅計該最新目錄 `.JPG`）。 |
| **單檔大小上限** | 待處理原圖 `.JPG` **< `16,711,680` bytes（`15.94 MiB`）** | `X.FINE` 高雜訊極端圖超過此限制時會安全略過，原圖無損。 |

## 五、日誌除錯與緊急停用／一鍵回滾路徑

可直接於 USB PMCA 模式使用 `--diag` 一鍵抓取全部日誌與狀態（存成 `a6400-diag-*.txt`），或於 `serviceshell` 手動檢視：
```sh
python3 tools/pmca_deploy_v3_clite.py --diag
# 或於 serviceshell 手動檢查：
/bin/busybox cat /tmp/a6400-hook-err.log 2>/dev/null
/bin/busybox cat /tmp_bt/a6400-film-boot.log
/bin/busybox cat /tmp_bt/a6400-film-capture.runtime.log
/bin/busybox cat /tmp_bt/a6400-film-capture.job.log
/bin/busybox cat /tmp_bt/a6400-film-capture.manifest
```

### 停用與回滾路徑（誠實邊界說明）

- **`/etc/ld.so.preload` 急停旗標與停用路徑**：開機掛勾 `/etc/a6400-autoexec.so` 會依序檢查 `/mnt/disable_hook`、`/mnt/disable.txt` 與 `/tmp/disable_hook`，開機啟動器亦檢查 `/mnt/A6400/DISABLE` 等旗標；但視系統階段 Linux 未必全程掛載記憶卡至 `/mnt`，因此若於現場欲緊急停用或升級前清除背景行程：
  1. **SD 卡開機前停用旗標（升級／除錯前最方便）**：於大容量儲存或讀卡機在記憶卡根目錄寫入 `/disable_hook` 與 `/A6400/DISABLE` 後重開機，可阻斷常駐行程載入，使 PMCA `054C:0CA8 → 054C:0336` 切換穩定不逾時；操作完成務必刪除此二檔。
  2. **一鍵恢復／卸載（`--rollback`）**：接回 USB 執行 `python3 tools/pmca_deploy_v3_clite.py --rollback`，會自動將 `.pre-v3c-backup` 還原（若原機無掛勾則乾淨移除 `/etc/ld.so.preload`、`/etc/a6400-autoexec.so`、`/tmp/autoexec.sh` 等檔案並 `sync`）。
  3. **機內持久化臨時停用（保留檔案）**：於 PMCA `serviceshell` 執行 `/bin/busybox touch /tmp/disable_hook && /bin/busybox sync`，拔線冷開機後即恢復原廠行為（日後 `rm /tmp/disable_hook` 可恢復）。
  4. **一鍵回滾其他版本**：將 USB 接回電腦，以指定舊版 `local-boot-package`（如 V3.1 歷史回滾基準 `package=5376263138a4a46c`）重跑 `pmca_deploy_v3_clite.py`。
  5. **Windows 使用者刷完恢復**：若使用建議的 **WSL2 + `usbipd-win`** 方案，在 PowerShell 按 `Ctrl+C` 停掉 `--auto-attach` 並拔線即自動恢復正常讀卡（無任何驅動殘留；下次不再穿透可直接 `usbipd unbind --busid <BUSID>`）。若為舊式原生 Zadig 用戶，於「裝置管理員」找到 `libusb-win32` 相機裝置 → 右鍵「解除安裝裝置」並勾選「刪除此裝置的驅動程式軟體」→ 重插相機即可恢復標準 `USBSTOR` 讀卡機。

## 六、完整實戰排雷手冊（部署過程中所有常見異常與解決對策）

以下整理從全新機身第一次寫入、跨版本升級到首次冷開機驗收，實機測試中**最容易遇到也最花時間的所有坑點與對應解法**：

| 階段 | 常見問題 / 現象 | 真正原因 | 實戰解決步驟 |
| --- | --- | --- | --- |
| **執行工具與環境** | `ModuleNotFoundError: No module named 'pmca'`，或 WSL2 `lsusb` 看不到相機／缺 `pyusb` | 尚未指定 `Sony-PMCA-RE` 目錄、用了 WSL1（不支援 USB）、未執行 `usbipd attach --wsl --auto-attach`、或未用 `sudo` | 1. 另行 `git clone https://github.com/ma1co/Sony-PMCA-RE`，執行部署／`--diag`／`--rollback` 時加上 `--pmca-dir /path/to/Sony-PMCA-RE`。<br>2. **Windows 10/11 務必用 WSL2**（`wsl -l -v` 確認為 `2`）＋ 在系統管理員 PowerShell 執行 `usbipd bind --busid <BUSID>` 與 `usbipd attach --wsl --auto-attach --busid <BUSID>`；WSL2 內安裝 `python3-usb libusb-1.0-0` 並以 `sudo` 執行。 |
| **USB 連線階段** | `No Sony devices found` 或完全偵測不到相機 | 使用僅供電充電線、相機不在「大容量儲存」、WSL2 尚未 `attach`、或（舊式原生 Windows）誤裝成 `WinUSB` | 1. 換用確定能傳資料的 Micro-USB **傳輸線**；相機 `MENU → 設定4 → USB 連線` 必選 **`大容量儲存`**（`USB LUN = 多重`）。<br>2. **Windows 10/11 請改用 WSL2 + `usbipd-win`**（並在 WSL2 跑 `lsusb` 確認出現 `054c:0ca8`），勿再依賴 Windows 原生驅動替換；僅舊系統備案時須用 Zadig 選 **`libusb-win32`**。<br>3. | **寫入 / 上傳階段** | 上傳中斷、`rc=None`、命令執行一半卡住，或 `--install-hook` 找不到 `/etc` hook | 1. Sony `serviceshell` 長命令易截斷。<br>2. 手動操作誤刪 `/tmp/a6400-autoexec.so`。<br>3. 忘了帶 `--install-hook`。 | 1. 全程使用 [`pmca_deploy_v3_clite.py`](../tools/pmca_deploy_v3_clite.py)（已拆塊 `<= 180` 字元＋`rc=None` 重試＋自動比對 SHA-256，重複重跑完全安全）。<br>2. 切記 **`/etc` 與 `/tmp` 共用 `/dev/nflasha10`**，嚴禁在安裝完 `/etc/a6400-autoexec.so` 後刪除 `/tmp/a6400-autoexec.so`。<br>3. 新機務必先從機身 `/usr/lib/libAK8975.so` 用 `build_autoexec_hook.py` 編出 `a6400-autoexec.so` 並加 `--install-hook`。 |
